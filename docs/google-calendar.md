## 目的

家族の予定を Google カレンダーと Family Office の両方で見られるようにし、二重入力と見落としを減らす。

## 現状（2026-11-27 時点）

- Google カレンダー連携のコードは存在しない
- カレンダー画面（`app/(main)/calendar.tsx`）は予定専用テーブルを持たず、`records` の期限・TODO、誕生日（`family_members` と知識ベース）、知識ベースの出来事を日付単位で集約表示している
- アプリ側のデータは日付（YYYY-MM-DD）のみで、時刻を持たない
- ダッシュボード（`app/dashboard.tsx`）も同じ集約結果から「今週の予定」などを表示している

## フェーズ 1: 読み取り（Google → アプリ）

### 認証

- ユーザーごとに Google OAuth で連携する。スコープはカレンダー読み取りの最小限にする
- リフレッシュトークンは Supabase 側（サーバー）に保存する。クライアント端末とリポジトリには置かない
- Google API の呼び出しは Supabase Edge Function 経由を基本とする（既存の secrets 運用に合わせる）

### 取り込み

- Edge Function が Google Calendar API から予定を取得し、専用テーブル（仮称 `google_calendar_events`）に保存する
- 保存項目の案: `household_id`、`google_calendar_id`、`google_event_id`、`title`、開始・終了（時刻とタイムゾーンを保持）、終日フラグ、場所、説明、Google 側の `updated`、同期日時
- 重複防止: （`google_calendar_id`, `google_event_id`）に一意制約を張る
- Google 側で削除された予定は、次回同期でアプリ側からも消す（キャンセル状態の反映方法は実装時に決めてここへ追記）
- 差分同期（syncToken）を使うか全件再取得にするかは実装時に決め、ここへ記録する

### 表示

- カレンダー画面の集約に種別 `google` を追加して混ぜる。ダッシュボードの「今週の予定」にも含める
- 時刻付き予定の表示方法（ラベルに時刻を含めるなど）は実装時に決め、ここへ追記する

## フェーズ 2: 書き出し（アプリ → Google）

- 書き出し先は、ユーザーの Google アカウント内に作る専用カレンダー「Family Office」。既存のカレンダーには書かない
- 対象は `records` の期限・TODO、誕生日、知識ベースの出来事。いずれも終日予定として書く
- 重複防止: Google 側の予定の `extendedProperties.private` に元データの（テーブル名, ID）を埋め込み、対応表テーブル（仮称 `google_calendar_exports`）にも Google 予定 ID を保存する
- 元データが変更されたら対応する Google 予定も更新する
- 元データの削除・TODO の完了時に Google 側をどうするかは未決事項（下記）

## フェーズ 3: 双方向同期（将来）

- フェーズ 1 / 2 の運用が安定してから判断する
- 競合ルール（例: 更新時刻が新しい方を正とする）を先に決めてから実装する
- 対象は時刻を持つ予定だけに絞る案を基本とする

## データ対応表（Google → アプリ）

| Google Calendar | アプリ側 |
| --- | --- |
| `summary` | タイトル |
| `start.dateTime` / `start.date` | 開始（終日かどうかで使い分け） |
| `end.dateTime` / `end.date` | 終了 |
| `location` | 場所 |
| `description` | 説明 |
| `updated` | 競合判定・更新検知 |
| `id` | `google_event_id`（重複防止のキー） |
